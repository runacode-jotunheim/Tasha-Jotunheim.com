# Backend для оплаты через Робокассу

Минимальный Node.js/Express сервер для `tasha-jotunheim.com`:
- `POST /api/create-payment` — фронтенд (корзина сайта) присылает список товаров и данные
  покупателя, сервер считает сумму, формирует подпись и возвращает ссылку на оплату Робокассы.
- `POST /api/robokassa/result` — сюда Робокасса сама стучится после реальной оплаты
  (server-to-server), сервер проверяет подпись Паролем №2 и присылает уведомление в Telegram.
- `GET /api/health` — проверка, что сервер жив.

## 1. Настройки в ЛК Робокассы (новый магазин)

Технические настройки магазина:

| Поле | Значение |
|---|---|
| Result URL | `https://ВАШ_ДОМЕН/api/robokassa/result` |
| Result URL — метод | POST |
| Success URL | `https://tasha-jotunheim.com/payment-success.html` |
| Success URL — метод | GET |
| Fail URL | `https://tasha-jotunheim.com/payment-fail.html` |
| Fail URL — метод | GET |
| Алгоритм хеширования | MD5 (уже стоит) |
| Система налогообложения | УСН доходы (`usn_income`) |

`ВАШ_ДОМЕН` — это домен/поддомен сервера на Timeweb Cloud, например
`api.tasha-jotunheim.com` (тогда нужно будет добавить A/CNAME-запись в DNS домена
tasha-jotunheim.com, указывающую на IP сервера Timeweb).

Пока магазин "в процессе активации" — работайте с `ROBOKASSA_TEST_MODE=1` в `.env`,
Робокасса добавит `IsTest=1` к ссылке оплаты и не будет списывать реальные деньги.

## 2. Деплой на Timeweb Cloud

1. Создать сервер (простого "облачного сервера" с Node.js или Docker достаточно —
   нагрузка минимальная).
2. Установить Node.js 18+ (`node -v` для проверки).
3. Склонировать репозиторий или просто скопировать папку `server/` на сервер.
4. `cd server && npm install`
5. `cp .env.example .env` и заполнить реальными значениями:
   - `ROBOKASSA_LOGIN` — MerchantLogin из ЛК
   - `ROBOKASSA_PASSWORD_1`, `ROBOKASSA_PASSWORD_2` — боевые пароли из Технических настроек ЛК
     (**никогда** не отправлять эти пароли в чат/почту/куда угодно, кроме
     самого `.env` на сервере)
   - `ROBOKASSA_TEST_PASSWORD_1`, `ROBOKASSA_TEST_PASSWORD_2` — **отдельная пара** для
     тестовых платежей, тоже из Технических настроек ЛК (обычно отдельным блоком/вкладкой
     рядом с боевыми паролями). Обязательны, если `ROBOKASSA_TEST_MODE=1` — без них
     Робокасса вернёт ошибку 29 "Оплата счетов недоступна"
   - `ROBOKASSA_TEST_MODE=1` пока магазин не в боевом режиме, `0` — когда реально принимаем деньги
   - `ALLOWED_ORIGIN=https://tasha-jotunheim.com`
   - при желании — `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` для уведомлений о заказах
     (бот создаётся за 1 минуту через @BotFather в Telegram)
6. Запуск: `npm start` (для продакшена лучше через `pm2` или systemd-сервис,
   чтобы сервер перезапускался сам при падении/перезагрузке).
7. Настроить HTTPS (например, через Nginx + Let's Encrypt / Certbot перед Node-сервером) —
   Робокасса требует https для Result URL.
8. Прописать домен `api.tasha-jotunheim.com` → IP сервера в DNS.
9. Проверить `https://api.tasha-jotunheim.com/api/health` — должен ответить `{"ok":true,...}`.

## 3. Что поправить на фронтенде

В `index.html` есть константа:

```js
var PAYMENT_API_BASE = 'https://api.tasha-jotunheim.com';
```

Заменить на реальный домен backend-сервера, когда он будет готов и привязан к DNS.
До этого момента кнопка «Перейти к оплате» в корзине корректно покажет пользователю
сообщение написать в Telegram вместо оплаты (не сломается молча).

## 4. Известные упрощения (на будущее)

- Номер заказа (`InvId`) сейчас генерируется по unix-времени в секундах — рабочий вариант
  для старта без базы данных, но два заказа в одну и ту же секунду дадут коллизию.
  Когда появится нормальная таблица заказов (например, в PostgreSQL на том же сервере),
  стоит заменить на автоинкремент оттуда.
- Цены товаров сервер сейчас берёт из того, что прислал фронтенд (без сверки с
  «эталонным» каталогом на сервере) — для сайта с ручной обработкой заказов это
  приемлемо, но при росте оборота стоит валидировать цены по серверному каталогу,
  чтобы исключить подмену суммы через консоль браузера.
- Уведомления о заказах идут в Telegram вместо полноценной БД заказов — рабочий
  вариант, пока заказов немного и Таша обрабатывает их вручную.
